# CLAUDE.md — enderecobr

**Project:** enderecobr — R package that standardizes Brazilian
addresses (street names, neighborhoods, municipalities, states,
CEP/postal codes) using string-manipulation rules (no
fuzzy/probabilistic matching), built on the Rust crate `enderecobr_rs`
via extendr **Maintainers:** Daniel Herszenhut (aut, cre), Rafael H. M.
Pereira (aut — Ipea), Lucas Mation (aut), Gabriel Garcia de Almeida
(aut) — Instituto de Pesquisa Econômica Aplicada (IPEA) **Repo:**
<https://github.com/ipeaGIT/enderecobr> (org migrated to
`ipea/enderecobr` — old URL redirects; git remote still points at
`ipeaGIT`, harmless but worth updating eventually) · **Branch:** main
**Language:** `Language: pt` in DESCRIPTION — NEWS.md, roxygen docs,
README, and most code comments are in Portuguese; match that for
user-facing content

## Core Principles

- **Plan first** — enter plan mode before non-trivial tasks; save plans
  to `quality_reports/plans/`
- **`R/` is authoritative** — `man/` and `NAMESPACE` are generated by
  roxygen2. Never hand-edit; edit the roxygen blocks in `R/` and run
  `devtools::document()`
- **Two backends, one release gate.** `R CMD check --as-cran` (0 errors,
  0 warnings, every note justified in `cran-comments.md`) gates the R
  side. A clean `cargo build` of `src/rust/` against the pinned
  `enderecobr_rs` version gates the Rust side — both must pass before
  merge or release.
- **`enderecobr_rs` is upstream, not vendored source.** The actual
  standardization logic lives in the sibling repo
  `ipeaGIT/enderecobr_rs` (published on crates.io). `src/rust/` here is
  a thin extendr wrapper crate around it. A reported bug is usually
  fixed **there** first — pulling the fix into this package means
  bumping the version pin in `src/rust/Cargo.toml`, not patching logic
  here. See
  [`r-extendr-conventions.md`](https://ipea.github.io/enderecobr/dev/~/.claude/rules/r-extendr-conventions.md)
  (global rule).
- **`[LEARN]` tags** — when corrected, or a non-obvious approach is
  confirmed, append `[LEARN:category] wrong → right` to
  [MEMORY.md](https://ipea.github.io/enderecobr/dev/MEMORY.md)

Cross-session context lives in
[MEMORY.md](https://ipea.github.io/enderecobr/dev/MEMORY.md); plans,
specs, and session logs are in
[quality_reports/](https://ipea.github.io/enderecobr/dev/quality_reports/).
Workflow rules, skills, and agents are configured globally at
`~/.claude` (shared with flightsbr / geobr / geobr-r-package) and apply
here via path-scoping — see “Skills Quick Reference” below for what’s
actually live in this repo.

## Commands

``` r

# Regenerate docs + NAMESPACE after editing roxygen blocks in R/
devtools::document()

# Run the test suite (includes Rust-backed functions + message/error snapshots)
devtools::test()

# Full CRAN-readiness check (slow — background + monitor for long runs)
devtools::check(args = "--as-cran")

# Test coverage
covr::package_coverage()
```

``` bash
# Bump the enderecobr_rs dependency to pull in an upstream fix/feature
cd src/rust && cargo update -p enderecobr_rs --precise X.Y.Z

# Regenerate R/extendr-wrappers.R — ONLY needed if the extendr-exposed function
# signatures changed upstream (not for internal-only fixes)
Rscript -e "rextendr::document()"

# Local R CMD check equivalent to CI
R CMD build . && R CMD check --as-cran enderecobr_*.tar.gz
```

**CRAN submission:** update `NEWS.md` + bump `Version` in `DESCRIPTION`,
refresh `cran-comments.md`, regenerate `src/rust/vendor.tar.xz` if
`Cargo.lock` changed, then `devtools::release()` (maintainer-only, not
automated).

## Package Functions

| Function | Purpose |
|----|----|
| [`padronizar_enderecos()`](https://ipea.github.io/enderecobr/dev/reference/padronizar_enderecos.md) | Flagship function — standardizes multiple address fields of a dataframe at once, given a field↔︎column mapping (built via [`correspondencia_campos()`](https://ipea.github.io/enderecobr/dev/reference/correspondencia_campos.md)) |
| [`padronizar_logradouros_completos()`](https://ipea.github.io/enderecobr/dev/reference/padronizar_logradouros_completos.md) | Standardizes + combines street-type, street-name, and number into one “logradouro completo” field |
| [`padronizar_logradouros()`](https://ipea.github.io/enderecobr/dev/reference/padronizar_logradouros.md) | Standardizes street names (abbreviation expansion, diacritics/casing) |
| [`padronizar_tipos_de_logradouro()`](https://ipea.github.io/enderecobr/dev/reference/padronizar_tipos_de_logradouro.md) | Standardizes street-type prefixes (e.g. “r” → “RUA”) |
| [`padronizar_numeros()`](https://ipea.github.io/enderecobr/dev/reference/padronizar_numeros.md) | Standardizes house/building numbers (S/N variants, leading zeros, format) |
| [`padronizar_complementos()`](https://ipea.github.io/enderecobr/dev/reference/padronizar_complementos.md) | Standardizes address complement fields (e.g. “qd 20” → “QUADRA 20”) |
| [`padronizar_ceps()`](https://ipea.github.io/enderecobr/dev/reference/padronizar_ceps.md) | Standardizes CEP (postal code) to `NNNNN-NNN`, validates digit count |
| [`padronizar_bairros()`](https://ipea.github.io/enderecobr/dev/reference/padronizar_bairros.md) | Standardizes neighborhood names |
| [`padronizar_municipios()`](https://ipea.github.io/enderecobr/dev/reference/padronizar_municipios.md) | Standardizes municipality names/codes via `codigos_municipios` |
| [`padronizar_estados()`](https://ipea.github.io/enderecobr/dev/reference/padronizar_estados.md) | Standardizes state names/codes/abbreviations |

All R-level functions follow the same pattern: `checkmate` input
validation → call the `*_rs()` extendr wrapper → `cli`/`rlang`-based
structured errors (`erro_endbr`) / warnings (`warning_endbr`). Follow
this pattern for any new function.

## Rust / extendr Notes

- `Config/rextendr/version: 0.4.2` in `DESCRIPTION` — this is a
  rextendr-scaffolded package.
- `SystemRequirements`: Cargo, `rustc >= 1.65` (DESCRIPTION) /
  `rust-version = "1.81"` (`src/rust/Cargo.toml` — the tighter
  constraint wins), `xz`.
- `tools/msrv.R` checks the installed Rust toolchain meets the minimum;
  `tools/config.R` (invoked by `configure`/`configure.win`) resolves
  CRAN-vs-dev build flags and Windows target triples
  (incl. `aarch64-pc-windows-gnullvm` for ARM64) before rendering
  `src/Makevars(.win)` from the `.in` templates.
- `src/rust/vendor.tar.xz` + `vendor-config.toml`: vendored crates.io
  deps (including `enderecobr_rs` itself) for CRAN’s offline build
  requirement. Regenerate with `cargo vendor` whenever `Cargo.lock`
  changes and before a CRAN submission — stale vendor tarballs break
  offline builds silently.
- Full conventions:
  [`r-extendr-conventions.md`](https://ipea.github.io/enderecobr/dev/~/.claude/rules/r-extendr-conventions.md)
  (global rule, path-scoped to `src/rust/**`, `Cargo.toml`,
  `Cargo.lock`, `configure*`, `tools/*.R`) — not yet created; see the
  pending workflow-adaptation plan.
